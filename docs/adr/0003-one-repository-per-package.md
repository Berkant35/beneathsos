# 0003. One repository per package, one local folder

- Status: Accepted
- Date: 2026-09-27

## Context

BeneathSOS is split into packages with different audiences:

| Package | Kind | Reused outside the app? |
|---|---|---|
| `ble_scanner` | Flutter plugin (Kotlin + Swift) | Yes — any app that needs raw BLE RSSI |
| `rubble_core` | pure Dart domain types | Possibly |
| `locator_engine` | pure Dart probability engine | Yes — research, other front ends |
| `rubble_canvas` | Flutter drawing and heatmap | Possibly |
| `beneathsos_app` | the Flutter app | No |

The maintainer wants each package to stand on its own on GitHub, so it can be found, cloned, reviewed
and later published to pub.dev independently, while still developing all of them together on one
machine.

## Decision

- Each package is its **own public GitHub repository** under `Berkant35`. The hub repository
  `beneathsos` holds rules (`CLAUDE.md`), documentation, research and tools.
- Locally, all repositories live under one folder:
  `beneathsos/` (hub) with `apps/` and `packages/` sub-folders, which the hub git-ignores.
- `pubspec.yaml` declares sibling packages as **git dependencies pinned to a tag**
  (for example `ble_scanner` at `v0.1.0`), so a fresh clone of any single repository resolves.
- A git-ignored **`pubspec_overrides.yaml`**, generated by `tools/link_local.sh`, points those
  dependencies to the sibling folders for local development.
- Releasing a package means tagging it (`vX.Y.Z`) and bumping the `ref` in its dependants.
- Shared governance files (licence, security policy, PR template, CI workflow) are copied from the
  hub with `tools/sync_governance.sh`.

## Alternatives

- **Monorepo with Dart pub workspaces and melos** — one clone, atomic cross-package commits, one CI.
  Originally chosen; replaced before any code depended on it because packages could not be presented,
  starred or versioned on their own.
- **Path dependencies committed to `pubspec.yaml`** — simplest locally, but every clone outside the
  maintainer's folder layout fails to resolve.
- **Publishing to pub.dev from day one** — premature while APIs change weekly.

## Consequences

- Each repository is understandable and usable alone; CI proves it, because it clones without the
  local overrides (the app's first CI run failed until `ble_scanner` was published with its tag).
- A change that spans packages needs one commit per repository and a tag bump; the dependency rules in
  `CLAUDE.md` §2 keep such changes rare.
- Contributors who work across packages must clone the hub, clone the others into `apps/` and
  `packages/`, and run `tools/link_local.sh` (documented in `CONTRIBUTING.md`).
- Governance files are duplicated per repository and must be re-synced after edits.
