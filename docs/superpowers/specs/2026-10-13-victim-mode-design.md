# Roadmap 10 — Victim mode: the trapped phone calls out

- Date: 2026-10-13
- Status: decided by the executor under the maintainer's blanket approval (2026-10-13)
- Builds on: `docs/architecture.md` §5.2, ADR 0007 (own BLE plugin, advertising later in the same
  plugin), ADR 0017 (victim mode in the dark, battery draining), `docs/fizibilite-2026-09-27.md` (iOS
  background advertising limits), CLAUDE.md §1 (offline; supports, never replaces, AFAD / 112)

## 1. Beacon (`ble_scanner` v0.2.0)

- `startAdvertising(AdvertiseConfig{serviceUuid, localName?, serviceData?})` (calling it again replaces
  the payload), `stopAdvertising()`, `advertisingSupported` in `capabilities()`; `onAdvertiseStarted()` and
  `onAdvertiseError(code, message)`. The Dart side rejects a payload that does not fit a legacy packet
  (service data ≤ 11 bytes, local name ≤ 20 bytes).
- Android (`BluetoothLeAdvertiser`, legacy, low latency, high power, not connectable): advert = flags +
  128-bit service UUID; scan response = service data. Android cannot advertise a custom local name
  (only the phone's own name), so `localName` is ignored there. Needs `BLUETOOTH_ADVERTISE` (12+).
- iOS (`CBPeripheralManager`): service UUID + local name (iOS cannot send service data). Foreground;
  `bluetooth-peripheral` background mode keeps it going in the overflow area (seen only by iOS scanners
  that look for the UUID — the screen asks to keep the app open).
- Scanning side: `ScanSample.serviceData` (UUID → bytes), both platforms.
- Not in v1: an Android foreground service for advertising after the app is closed (backlog).

## 2. Payload (BeneathSOS beacon v1)

- Service UUID `06ad86ef-1e8c-47b4-9c65-c526d5e31581`. Beacon id: 16 random bits drawn once per
  victim-mode start — the identity that survives address rotation. iOS sends it as the local name
  `SOS-XXXX` (4 hex digits).
- Service data (Android), 5 bytes: version `1`, beacon id (2 bytes, big-endian), battery % (`0xFF`
  unknown), minutes since the last touch or movement (0–254, `0xFF` = 255 or more). A rescuer sees
  "touched 3 min ago" — a sign of life, never a claim about the person's state.
- UUIDs are compared case-insensitively (Android reports lower case, iOS upper case).

## 3. Victim screen (`/victim`, `features/victim`)

- Opens straight from home, no disclaimer gate (a trapped person cannot read a page of text).
  Starts advertising at once; full-bleed, dark, large text: "Your phone is calling out to rescuers",
  "Stay calm, save battery, keep this screen open", the beacon id, battery, and **Call 112** guidance.
- Sealed `VictimState`: starting / needs permission (button) / Bluetooth off / calling out (since,
  beacon id) / not supported / failed. Notifier is thin: `StartBeacon` / `StopBeacon` use cases over a
  `BeaconPort` (`core/services/beacon_service.dart` wraps the plugin).
- Liveness: a tap anywhere, or motion (MotionPort), resets "last touch"; the payload is refreshed every
  minute and on battery change (`BatteryPort`, battery_plus). Screen kept awake (wakelock), dark theme.
- **SOS sound** button: loud 3 kHz beep pattern (asset generated by a script, `audioplayers`) until
  tapped again; a rescuer's ear finds the last metres.
- Leaving the screen asks "Stop calling out?" and stops advertising.

## 4. Rescuer side (`features/targets`)

- A sample whose service UUIDs or service data hold the beacon UUID is `DeviceKind.trappedBeacon`; its
  key is `sos-XXXX` from the beacon id (service data, else local name), so address rotation does not
  split it. Ranked first with the reason
  "This phone says it is trapped (BeneathSOS victim mode)" and, when present, battery and last touch.

## 5. Testing

Plugin: Dart API tests (config, payload limits, callbacks to streams); native code is compiled (Android
APK, iOS archive) and tried on a phone. App:
payload encoding (battery, minutes cap, unknown battery), state machine with a fake `BeaconPort`
(permission denied, Bluetooth off, unsupported, failure), liveness reset, Back asks before stopping,
SOS toggles the sound port, EN/TR, 200 % text; rescuer classification and key.
